Invoke the write-ord skill. Ingests a call transcript, meeting notes, document, or conversation context and synthesizes it into a structured Operational Requirements Document (ORD) organized by ISO/IEC 25010:2023 quality characteristics (Performance Efficiency, Reliability, Security, Compatibility, Flexibility, Maintainability, Interaction Capability, Functional Suitability, Safety). Runs in two phases: Phase 1 (AFK) extracts and classifies all operational requirements from the source material and presents a summary for confirmation; Phase 2 (HITL) writes the ORD after confirmation, plus an LLM companion (`-ORD.llm.md`) beside it — the same content restructured for a language model to consume, never the reviewed artefact. Run with `--llm-only [ORD path]` to regenerate the companion from an existing ORD. Pass the source material directly in the conversation or as a file path. Use when you want to formalise operational requirements from any unstructured source.
